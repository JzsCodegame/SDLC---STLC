# Mini Quiz Academy automation lab infrastructure

This package describes a dedicated Coder control plane and one DigitalOcean Droplet per student workspace. Each workspace has a separate 25 GiB block volume mounted at `/home/coder`. Coder proxies the browser IDE, live Chromium desktop, and practice app preview as owner-only subdomain apps. The student VM has no inbound firewall rule, Docker socket, DigitalOcean token, or control-plane database secret.

## Before any cloud launch

The reviewed practice app must be committed to a readable GitHub repository at `automation-lab/practice-app`, and `template/terraform.tfvars` must pin that exact commit. Confirm DigitalOcean quota, actual subscription balance, allowed region, DNS ownership, wildcard certificate, and a spend cap. The 50-student target is a capacity objective, not a tested claim. This checkout has no live cloud deployment. The base Compose file deliberately publishes **no** host ports until the first Coder admin is created and verified.

The control-plane host must be dedicated Linux with Docker Compose, at least 2 vCPU/4 GiB for Coder itself, persistent disk for the PostgreSQL and Coder volumes, and backups. Do not use the existing Windows Docker Desktop or restart existing services. Obtain a certificate that covers both `lab.example.org` and `*.lab.example.org`; place `fullchain.pem` and `privkey.pem` in ignored `certs/`, with owner-only permissions. Create DNS A/AAAA records for the base and wildcard names pointing to the control-plane host. Cloud workspaces connect outbound to `CODER_ACCESS_URL` over HTTPS.

Copy `.env.example` to ignored `.env` on that host and set a real domain, random alphanumeric PostgreSQL password, and a narrowly scoped DigitalOcean API token held only in the Coder service. Keep `.env`, certificate keys, Terraform state, and rehearsal tokens private. A dedicated DO project, token, quota and cost alerts should be set before creating workspaces. Coder's provisioner must have the DO rights required for Droplets, Volumes, firewalls and tags; a read-only token will not work.

## Private first-user bootstrap

1. Run `docker compose --env-file .env -f compose.yaml config --quiet`, then `docker compose --env-file .env -f compose.yaml up -d`. This starts PostgreSQL, Coder, and Caddy without publishing ports.
2. Run `docker compose --env-file .env -f compose.yaml exec coder /opt/coder server create-admin-user` interactively. Set a strong admin password through the prompt; do not place it in a shell argument or `.env`.
3. Run `docker compose --env-file .env -f compose.yaml exec coder /opt/coder login http://127.0.0.1:7080` and authenticate as that admin. Run `docker compose --env-file .env -f compose.yaml exec coder /opt/coder whoami --output table --column username,roles`; verify the expected admin identity and Owner role before public exposure.
4. Confirm the cert covers base and wildcard names, both DNS names resolve to the intended host, and `curl --resolve`/TLS checks succeed from an operator machine. Only then run `docker compose --env-file .env -f compose.yaml -f compose.public.yaml up -d`. `compose.public.yaml` is the sole file that publishes 80/443. Check HTTPS login and a private app through the public hostname.

The normal student path uses Coder password accounts created by an admin, with temporary passwords delivered through the school's existing private channel. Example: `coder users create --username student01 --email student01@example.org --login-type password` (the CLI prompts for the password when omitted). Students sign in and create their own workspace from the template. Do not equate an academy site login with a Coder account; there is no Firebase or academy SSO bridge in this package.

## Template and workspace lifecycle

From the authenticated admin CLI, run `coder templates push mini-quiz-lab --directory template --variables-file template/terraform.tfvars` after copying `terraform.tfvars.example` to `terraform.tfvars` and setting the published commit. `terraform init -backend=false`, `terraform fmt -check`, and `terraform validate` should pass on an operator machine before pushing. Terraform 1.13.5 was downloaded from HashiCorp with its published SHA256 verified. Init, fmt -check, and validate passed locally; the final validation had zero errors and zero warnings. Coder's provider and DigitalOcean provider versions are pinned in `main.tf`; Coder, PostgreSQL, and Caddy image tags are pinned in Compose. The provider lockfile includes signed checksums for Windows and Linux amd64. Verify container image digests before production promotion.

Starting a workspace creates a firewall before a Debian 12 VM and attaches its private volume. Cloud-init refuses to start student services unless the volume mounts. First boot downloads and verifies pinned Node 24.21.0, PowerShell 7.6.6, and code-server 4.139.1 archives, installs Debian-packaged Git/Chromium/noVNC and browser dependencies, clones the pinned practice app commit, runs `npm ci`, installs the Playwright/Cypress browsers, builds the app, then starts Coder agent and private apps. This cold path can take minutes; prewarm with a real pilot and measure it. Browser IDE terminals default to PowerShell 7; Git, Node and npm are installed. The interactive Chromium desktop is exposed through noVNC on an owner-only Coder app; test scripts can use `DISPLAY=:99`. The preview listens on loopback port 4173 with `LAB_MODE=true` for classroom reset and stores tickets in `/home/coder/data`.

Stopping a workspace deletes its VM and firewall while retaining the named 25 GiB volume. A later start creates a VM, remounts the volume and preserves student Git commits, browser profile, test caches and app data. The seed commit is only checked out when the volume is first initialized; later starts never reset the repo. The volume has `prevent_destroy`, so **workspace deletion intentionally fails** until an operator exports or confirms disposal of student data and explicitly removes that guard for that workspace. This is a billable retention policy, not automatic cleanup. Verify the volume ID and backup/snapshot before any offboarding deletion; do not erase student work as routine cleanup.

## Capacity and acceptance

Run a pilot with one real student account, then 10, then 50 distinct accounts and active workspaces. Do not proceed to the next cohort if the prior cohort fails. For each cohort, use the real Coder CLI and per-student tokens in an ignored `evidence/private/tokens.json` file shaped as `[{"username":"student01","workspace":"lab","token":"..."}]`. From an operator machine with the matching Coder CLI: `CODER_URL=https://lab.example.org node scripts/rehearse.mjs evidence/private/tokens.json 1 evidence/private/rehearsal-1.json`, then repeat with 10 and 50. It runs 1/10/50 concurrent **real** Coder SSH sessions; each checks app, IDE, noVNC and headed Playwright. The report omits token and command output. This is a workload check, not proof of isolation or persistence.

Separately, verify in a real browser as each pilot account: Coder login; IDE PowerShell default; Git/Node/npm; visible Chromium through the Browser app; app preview, ticket persistence and test reset; Playwright headed and Cypress open. Attempt another student's owner-only app URL and workspace SSH with a different account and require denial. Stop one workspace, verify VM removal and volume retention, restart it, and verify a unique file, Git commit and ticket survive. Check that no worker public port or metadata endpoint is reachable from the student account. Record Coder agent health, startup time, control-plane CPU/memory, and cloud cost at each stage. Only a 50/50 workload report plus these separate acceptance gates supports a 50-student readiness claim.

At published list prices, 50 continuously running 2 vCPU/4 GiB Basic Droplets at about $24/month each plus 50 retained 25 GiB volumes at about $2.50/month each would be roughly $1,325/month before the control plane, bandwidth, backups, taxes and other charges. Actual billing depends on usage and plan. Stopped workspaces still retain billable volumes. Set an actual spending ceiling and quota with DigitalOcean before scaling.

## Local validation and current evidence

`node scripts/static-check.mjs` and `docker compose -f compose.yaml config --quiet` pass on the shared Windows host with placeholder environment values. Terraform init and schema validation passed, including a provider lock for Linux amd64; Git Bash parsed bootstrap.sh with bash -n successfully. The Docker Linux daemon is unavailable. No container or Linux service boot, cloud apply, Coder-authenticated browser proxy smoke, or 50-workspace rehearsal has been completed. Pattern assertions and syntax/schema checks do not establish runtime readiness.
