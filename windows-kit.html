WINDOWS STUDENT GUIDE · KIT 1.1.0

Download. Set up. Watch your first test.

Choose the mouse steps or the PowerShell steps. Both use the same kit. Complete the shared download and setup steps, then choose the separate Playwright or Cypress guide below. These instructions install tools on your Windows 10/11 x64 desktop; the instructor-hosted browser workspace has its own workspace login.

You need Internet access and at least 2 GiB of free disk space. Setup checks Node 24, Git, Edge/Chrome and VS Code, then installs the practice app, Playwright and Cypress.

Download Windows kit 1.1.0 →

Save the ZIP in Downloads using its original filename. Do not run the kit inside the ZIP.

1. Extract the ZIP

Option A · Use your mouse

  1. Open File Explorer → Downloads.
  2. Right-click mini-quiz-lab-1.1.0-windows.zip → Properties. If Unblock appears, select it and click Apply.
  3. Right-click the ZIP → Extract All. Set the destination to Academy-Lab-1.1.0 inside Downloads, then click Extract.
  4. Open that folder, then its inner Mini Quiz Lab 1.1.0 folder.
  5. Choose View → Show → File name extensions to distinguish Setup.cmd from Setup.ps1.

Option B · Use PowerShell

Open Start, search for Windows PowerShell and open it. Type one line at a time and press Enter:

cd "$env:USERPROFILE\Downloads"
Get-ChildItem ".\mini-quiz-lab-1.1.0-windows.zip"
Unblock-File ".\mini-quiz-lab-1.1.0-windows.zip"
Expand-Archive -LiteralPath ".\mini-quiz-lab-1.1.0-windows.zip" -DestinationPath ".\Academy-Lab-1.1.0"
cd ".\Academy-Lab-1.1.0\Mini Quiz Lab 1.1.0"
Get-ChildItem Setup.cmd, Lab.cmd

cd changes your current folder. Get-ChildItem checks the file exists. Unblock-File removes the download mark from this ZIP. Expand-Archive extracts it. The second cd enters the kit folder.

If your download is elsewhere, replace the first path with that folder’s full path in quotes. If the ZIP cannot be found, stop and check its name/location. If the destination already exists, use your existing kit; do not overwrite it.

Check: you can see Setup.cmd and Lab.cmd outside the ZIP.

2. Install and check the tools

Option A · Double-click

Double-click Setup.cmd. Keep its window open until SETUP SUCCEEDED appears.

Option B · PowerShell

From the kit folder reached in step 1, run:

.\Setup.cmd

.\ means “run the file in this folder.” When Setup asks you to press a key, do so to return to PowerShell.

Automatic setup checks: Node.js 24, Git 2.40 or newer, Edge or Chrome 140 or newer, and VS Code 1.90 or newer. Setup also installs the practice app’s pinned Playwright and Cypress dependencies and verifies the Cypress binary.

Compatible tools print PASS and are kept. Missing or unsupported tools are installed or updated, then checked again. Approve a named installer if Windows asks. Setup installs the pinned app/test dependencies, verifies Cypress and builds the Help Desk. It can take several minutes; wait for the final message.

Ready: SETUP SUCCEEDED. Stopped: SETUP STOPPED. Read the first error above it, fix it and rerun Setup.cmd. Repeating setup preserves your working copy.

Setup troubleshooting and optional updates

If App Installer is missing, install/update it from Microsoft Store. A school-managed PC may need its administrator. Do not disable security settings. To request updates for compatible Git/browser/editor installations, run .\Setup.cmd -UpdateTools; ordinary setup already repairs missing or unsupported prerequisites.

3. Open PowerShell in the right folder

If you used PowerShell above, stay in that window. If you double-clicked Setup, open Windows PowerShell from Start and run:

cd "$env:USERPROFILE\Downloads\Academy-Lab-1.1.0\Mini Quiz Lab 1.1.0"
Get-Location
Get-ChildItem Lab.cmd

Use your actual extraction path if you chose another destination. Keep quotes around paths containing spaces. Get-Location shows where you are; the next command must list Lab.cmd. A prompt starting at C:\Windows\System32 is fine—cd moves you to the kit.

If “Lab.cmd is not recognized” appears: run the cd command above and check Lab.cmd again. Run kit commands from this folder.

Playwright guide

After shared setup steps 1–3, follow this section to run, inspect and edit Playwright tests.

A. Run your first visible Playwright test

.\Lab.cmd test playwright-headed

This builds your saved app, starts its own test server and opens a real browser. Watch it create/search/update Help Desk tickets. Actions are slowed for teaching. You do not need to run “start” first. Keep the terminal open; the browser closes after tests finish.

The unchanged kit has six example tests. Look for 6 passed in the terminal. After editing, a failed check shows a failure and its evidence.

Then open the report:

.\Lab.cmd report

B. Open your files, edit and run again

.\Lab.cmd folder

This opens your editable practice folder in File Explorer and prints its exact path. In VS Code, choose File → Open Folder and select that folder. Open tests/playwright/help-desk.spec.ts, change a test and press Ctrl+S to save.

Return to the original kit PowerShell window and rerun:

.\Lab.cmd test playwright-headed

Edit the copy in Mini Quiz Student Work\1.1.0\practice-app, beside the kit. Keep the downloaded template unchanged. Back up Student Work to retain tests and notes.

Cypress guide

Cypress is another way to test the same Help Desk. Complete setup and folder checks in steps 1–3 first. You can choose this walkthrough instead of the Playwright walkthrough. Cypress runs locally without a Cypress Cloud login or paid subscription.

A. Open Cypress from the kit folder

Mouse option: double-click Lab.cmd, type 6 for Open Cypress and press Enter.

PowerShell option: open Windows PowerShell and enter these lines, pressing Enter after each. Use your actual extraction folder if it differs:

cd "$env:USERPROFILE\Downloads\Academy-Lab-1.1.0\Mini Quiz Lab 1.1.0"
Get-ChildItem Lab.cmd
.\Lab.cmd test cypress-open

The command builds your saved practice app, starts its isolated Cypress test server on port 4175 and opens Cypress. Keep this terminal open throughout the session. You do not need to run .\Lab.cmd start first.

B. Choose E2E Testing

If a “What’s New” screen appears, click Continue. On the welcome screen, click E2E Testing, which should say Configured. The existing kit already supplies its configuration and example test.

C. Choose your browser and start

Select Edge or Chrome, then click Start E2E Testing in Edge (or Chrome). This opens the Cypress runner in a separate browser window. You can leave the Cypress desktop window open behind it.

D. Run the example and read the result

On the Specs page, under cypress\e2e, click help-desk.cy.ts. A spec is a file containing tests. You do not need to create a new spec to run this example.

The left side lists tests and their commands. The right side shows the real Help Desk as Cypress operates it. Green checks mean assertions passed; a red test means a check failed. Expand a test and select or hover over its commands to inspect the recorded page state.

Success: all six original tests show green checks. To repeat the current spec, click the circular Rerun all tests button above its command list. Cypress can also rerun automatically when you save a spec while it is open.

E. Write your first Cypress test

Keep Cypress open. Open a second PowerShell window, change to the same kit folder and run:

cd "$env:USERPROFILE\Downloads\Academy-Lab-1.1.0\Mini Quiz Lab 1.1.0"
.\Lab.cmd folder

In VS Code, choose File → Open Folder and select the editable folder that opened. Inside cypress → e2e, create my-first-test.cy.ts. Paste this complete test and press Ctrl+S:

describe('My first Help Desk test', () => {
  beforeEach(() => {
    cy.request('POST', '/api/test/reset');
    cy.visit('/');
  });

  it('creates a ticket with Open status', () => {
    cy.get('#student').type('Practice Student');
    cy.get('#title').type('My first Cypress ticket');
    cy.get('#description').type('A fictional ticket for class practice.');
    cy.contains('button', 'Create ticket').click();
    cy.contains('.ticket', 'My first Cypress ticket')
      .should('contain.text', 'Open');
    cy.get('[data-testid="ticket-count"]').should('have.text', '4');
  });
});

Given: reset the isolated test records and open the app. When: fill the form and create a ticket. Then: confirm its title, Open status and the count of four tickets. cy.get finds an element; type enters text; click performs an action; should checks the outcome. Cypress queues these commands; do not add Playwright-style await to them.

Return to Cypress → Specs and click my-first-test.cy.ts. Look for one green test. Change the title in both the input and assertion, save, and watch it rerun. Edit your Mini Quiz Student Work copy; keep the downloaded kit template unchanged.

F. Run every spec from the terminal, then stop cleanly

Close the Cypress-controlled test browser and the Cypress desktop window. If the original command is still waiting, press Ctrl+C in its terminal. Wait until the PowerShell prompt returns before starting another run.

.\Lab.cmd test cypress

This runs all matching specs without the interactive runner and prints results in the terminal. The original kit has six tests; adding the example above gives seven. A successful run exits automatically. To return to the visible runner, use .\Lab.cmd test cypress-open.

Where are results? Use the Cypress command list while open, or terminal summary after a noninteractive run. Failed noninteractive runs save screenshots under cypress/screenshots in your working copy. Videos are disabled in this kit. .\Lab.cmd report opens the Playwright report; it does not display Cypress results.

Cypress troubleshooting: what to check first
Lab.cmd cannot be found
Repeat the cd command above, then Get-ChildItem Lab.cmd. Run the launcher from the kit folder.
Cypress is missing or cannot start
Close the runner, rerun .\Setup.cmd and wait for SETUP SUCCEEDED. Setup installs and verifies the pinned Cypress binary.
E2E is not configured, or the spec list is empty
Confirm you opened Cypress with the kit command. Your editable practice folder must contain cypress.config.ts and cypress/e2e/help-desk.cy.ts. Clear the Search specs filter. Do not generate replacement configuration to hide the problem.
No Edge/Chrome choice
Close Cypress, rerun Setup.cmd to check/install prerequisites, then reopen it.
Port 4175 is unavailable
Finish your previous Cypress session, close its windows and stop its launcher with Ctrl+C. The kit will not stop unrelated programs automatically. Run one suite at a time.
The app cannot be reached
Check that the launcher terminal remains open and reported the test server ready. A manually started app on4173 is separate. Stop the failed Cypress session and relaunch using the kit command.
A test is red
Expand the failed test, read its first failed command, compare the expected value with the app, correct the test or app, save and rerun. A wrong expected count should fail; do not remove the assertion just to get green.
