In the Windows student practice-app folder

$env:PLAYWRIGHT_CHANNEL = 'msedge'

Use the installed Edge channel. Close a previous test runner before starting another. Do not target the public browser-only practice website with this Help Desk spec.

Read results and preserve evidence

The terminal must show your test names passing. Other existing tests may also run. On a failure, read the expected and actual result and keep test-results and playwright-report. On Windows, run npm run report:playwright inside practice-app to open its local HTML report. In the workspace, use the editor to inspect saved report files; report ports are not automatically public routes.

Save the editor file before running. After a finished run, $LASTEXITCODE should be 0. A failure is useful evidence; describe its cause and your correction before rerunning.

GUIDED → INDEPENDENT

Four exercises. One application.

Make a failure you can explain.

  1. Run the create/reload worked test successfully.
  2. Change its expected status from Open to Resolved. Keep the application unchanged.
  3. Run it and record the failing line, expected status and observed status.
  4. Explain why the requirement still says Open. Restore the assertion, save, and rerun.

Do not remove the assertion or add a long sleep to manufacture a green result. Restore the correct expectation before the final regression run.

The same check in Cypress

Playwright is the main tool in this class. Cypress uses a different command style to check the same behavior. Study this comparison after completing your Playwright exercises; Selenium and API-focused Karate/JUnit remain later extensions.

cy.get('#student').type('Practice Student');
cy.get('#title').type('Class Two Cypress ticket');
cy.get('#description').type('A fictional practice issue.');
cy.contains('button', 'Create ticket').click();
cy.contains('.ticket', 'Class Two Cypress ticket').should('contain', 'Open');

This is a comparison fragment, not a standalone spec. The existing Cypress suite provides its fixture and app server. In the workspace use academy-test cypress; in the Windows practice-app folder use npm run test:cypress. Do not run it alongside the other suite.

Your Class Two submission

  • Your saved class-two.spec.ts with a requirement stated in each test name.
  • A passing run and its report or terminal evidence.
  • One failure note: expected/actual, cause, correction and rerun result.
  • An independent extension: a two-character title boundary, an In progress filter, or an exact-title search.

Homework: add a test proving Cancel keeps a ticket’s status unchanged. Start with a known ticket, choose a different status, cancel, reopen and verify the original status. Explain the regression risk it protects.

Before stopping: save the file and evidence in the student workspace, then use the portal’s Save and stop control. Instructor assessment checks the behavior and your explanation, not just the number of green tests.
